Безопасность

Что Kryonux защищает, что для этого включено, чего пока нет и как сообщить об уязвимости. Всё ниже взято из файлов репозитория, в таблице указано, из каких.

Модель угроз

УгрозаЧто делает система
Атака по сетиФаервол с политикой drop на входе, ssh только по ключам, лишние сетевые протоколы отключены
Повышение прав локальным пользователемЯдро с kspp-опциями, ограничения ptrace, bpf, kexec, dmesg, административные команды через doas
Подмена iso или исходниковSHA-256 iso и исходников, подпись minisign, attestation происхождения в github actions
Кража дискаLUKS2 по желанию, опционально tpm2 (pcr 7); скрипт tpm2 на железе не проверен
Подмена загрузчика и ядраСкрипты secure boot со своими ключами, подпись limine, хеши ядра, uki (только uefi); на железе не проверялись

Проверить свою установку: doas kryonux-audit и doas kryonux-audit --cis.

Чего пока нет

  • Готовых профилей AppArmor и userspace-утилит нет: профили нужно добавлять отдельно
  • UKI, tpm2 и модуль dracut не проверены на железе
  • TPM2 привязан к pcr 7 (состояние secure boot), а не к хешу ядра
  • Ключ подписи minisign хранится в секретах github actions: подпись доказывает, что файл собран workflow проекта, а не что ключ лежит офлайн
  • Независимого аудита кода и сборки нет
  • Live iso содержит известный пароль (пользователь Kryonux, пароль Kryonux), ssh для него закрыт; в установленной системе его нет

Как проверить скачанное

Проверь sha256 и подпись minisign файла из релиза. Публичный ключ проекта лежит на сайте.

Как сообщить об уязвимости

Не пиши об уязвимости в публичный issue. Открой приватное сообщение на github (вкладка security, report a vulnerability). Укажи версию, шаги воспроизведения и что можно сделать с уязвимостью.
